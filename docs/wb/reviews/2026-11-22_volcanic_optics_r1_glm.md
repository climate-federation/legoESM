# Findings

**1. MAJOR — `compiled_segments.py:1092` — `aerosol_sw_volc` added to `GRID_SHAPED_FORCING_FIELDS`, but it is not grid-shaped.**
Every other member of that tuple (`sfc_sw_up`, `aerosol_ccn_aod`, `o3_top_vmr`, …) is `(ncol,)`. `aerosol_sw_volc` is `(ncol, nlev, 3, 14)`. Unlike `aerosol_lw_od` (also `(ncol, nlev)`), which is pointedly *not* in this tuple. If that tuple drives column-wise gather/scatter, reduce/mean across ranks, or time-averaging of forcing fields, the 4-D array will either shape-error on the SPMD path or be silently averaged across the wrong axes. Failure scenario: multi-rank compiled segment with volcanic forcing → crash or corrupted volcanic optics. Verify the consumers of this tuple; if they only pass fields through, downgrade, but then the membership is misleading and `aerosol_lw_od`'s absence is inconsistent.

**2. MAJOR — `subcolumns.py:416` — per-subcolumn expansion of the (ncol, nlev, 3, 14) field.**
Adding `aerosol_volcanic_moments_sw` to `PER_COLUMN_SOLVER_KEYS` means MCICA duplicates the full moment tensor per subcolumn. At res6 (~10⁶ columns, 32 lev, 3×14 moments, float32) that is ~5.4 GB for one copy and `nsub`× that inside the subcolumn solve — versus ~130 MB for the old grey `(ncol, nlev)` field. The host-side interpolation (`surface_utils.py`) also materializes `(3·14, ncol, 70)` vmap inputs plus the `(ncol, 70, 3, 14)` source before remap (~11 GB peak at 10⁶ columns). This needs a measured memory budget or a band-looped/vmapped-with-lower-peak rewrite before production-resolution AMIP runs.

**3. MINOR — `rrtmgp.py:881-884` — overhead-layer zeros added only inside the `_zero(aerosol_od)` branch.** If any path ever constructs the overhead layer without triggering that branch (e.g. `aerosol_optical_depth is None` but o3 overhead still built — as in the probe's "file" arm where an explicit zeros `aerosol_optical_depth` is passed), the volcanic halo prepend is skipped and shapes mismatch. The tests pass `aerosol_optical_depth=0` explicitly, masking this. Confirm the branch condition is "overhead layer exists", not "grey aerosol present".

**4. MINOR — `external.py` (`get_aerosol_sw_volcanic_optics_at_time`) — `loaded[:4] + (loaded[4],)` is just `loaded[:5]`.** Cosmetic, but it suggests the trailing-band plumbing was retrofitted; `band_wn` bypasses time/lat interpolation correctly (it's constant), so no functional issue.

**5. MINOR — hardcoded `_RRTMGP_SW_BAND_LIMITS_CM1`.** Duplicating the table is fragile, but the test pinning it to both g112/g224 files is adequate mitigation, and a config with a *different* SW gas table fails loudly (loader or `solve_columns` shape check), never silently. Acceptable.

**6. MINOR — behaviour changes for non-default configs are all loud, but note them:**
(a) a CMIP6 file with `ext_sun` but no `omega_sun`/`g_sun` now **raises** where it previously ran grey (voted, but it converts a working legacy setup into a crash — release-notes item); (b) gray/zero radiation + such a file now raises (voted Q5); (c) legacy column-`aod` files and no-volcanic runs are byte-identical (`volc_opt is None` → old column path, `aerosol_sw_volc=None` threaded as None everywhere, no sharding, no kwargs) — verified through model_driver, hydrostatic, spectral_pe, compiled, SPMD, and MC-field paths; I found **no path that receives `aerosol_od` and silently drops the new field**.

**7. Band mapping/order — checked, correct.** Loader sorts by ascending wavenumber with the 2600/2680 edge exemption, layer axis flipped to ascending pressure consistently with `p_edges`; `moveaxis((2,3),(0,1))` + lev-reverse + halo reshape + reshape to `(3, n_bnd, ncol, 1, nlev+2)` preserves index order (contiguous flatten); `g_point_to_bnd[igpt]` indexes the band axis of the `(3, n_bnd, …)` tensor correctly in both the g-point loop and the clear-sky co-solve. Moment mixing in `_mix_sw_aerosol_and_clip` is the exact linear combination (verified by the 1e-10 grey-equivalence test), so no double counting: `aerosol_od` gets the troposphere-only config when `volc_opt` is present, and CCN is unchanged. Budget closure is tested at 1e-10·incident.

**8. MINOR — test vacuity check: not vacuous.** Grey-equivalence, refusals, band-table pinning, jit/grad-vs-finite-difference, and driver-placement tests all assert real values. Two soft spots: `test_production_file_maps_and_sulfate_scatters` is skipif-gated on a scratch path (production validation may never run in CI), and the probe's `(1, nsrc, 42)` reshape hardcodes 14 bands (fine while the band table is pinned).

**9. MINOR — pytree/AD.** `None`-vs-array across segments follows the existing `aerosol_lw_od` pattern (forcing dict `.get` at closure build time → recompile, not error); float32 cache + `_table_dtype` cast under compute_fp32 is handled; halo `clip(0, None)` is a.e. differentiable and gradient is tested against finite differences.

# VERDICT

**Approve with required follow-ups.** The physics, band ordering, energy accounting, and no-volcanic/legacy-file backward compatibility are correct and well tested; I found no silent drop path and no double counting. But **finding 1** (`GRID_SHAPED_FORCING_FIELDS` membership of a 4-D field — verify or remove before merge) and **finding 2** (subcolumn + host-interpolation memory at production resolution) must be resolved/measureed before this runs at res6; **finding 3** should be confirmed non-conditional on the grey aerosol being present.
