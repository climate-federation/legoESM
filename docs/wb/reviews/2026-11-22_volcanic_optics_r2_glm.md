## Findings

1. **MEDIUM — `physics_pipeline.py` simple_lw builder not extended.** The diff extends `_build_none_radiation_fn`, `_build_gray_radiation_fn`, `_build_rrtmgp_radiation_fn` with `aerosol_sw_volc_col`, but the `simple_lw` builder (if it exists as a sibling, e.g. `_build_simple_lw_radiation_fn`) is not in the diff. Failure scenario: a `simple_lw` deck whose volcanic file has `ext_sun` reaches `physics_pipeline(..., aerosol_sw_volc_precomputed=...)` → `{"aerosol_sw_volc_col": ...}` is splatted into the builder call (`physics_pipeline.py:3336`). If the builder's signature lacks the kwarg → `TypeError: unexpected keyword argument` at build time (loud but wrong message, and NOT the `ValueError` the integration-layer guard promises — note this pipeline path bypasses `_call_radiation_backend` entirely, so that guard never fires here). If the builder has `**kwargs`, it's a **silent drop** — the exact defect codex 2 fixed for gray/simple_lw, reintroduced one layer down. Verify and mirror the gray refusal (the new test only exercises `_build_gray_...` and `_build_none_...`).

2. **LOW — band-edge validation is against a hardcoded table, not the live gas-optics file** (`external.py`, `_RRTMGP_SW_BAND_LIMITS_CM1`). The loader checks the *file* against this constant; the runtime check in `rrtmgp.py:1131` is a `(3, n_bnd)` *count* check only. A nonstandard SW table with 14 bands but different limits would map the volcanic bands silently wrong. Mitigated by `test_band_limit_table_equals_rrtmgp_files` pinning both shipped tables; acceptable, but a comment-to-code drift risk if a table is ever regenerated.

3. **LOW — hard refusal on any negative `g_sun`** (`external.py`, `np.any(g < 0.0)` raise). Real CMIP6 volcanic files can carry slightly negative g in the far-IR/UV tail bands; the moments code already clips `g` to `[-1, 1]` for the product, and a physically harmless −0.01 in the 820–2680 cm⁻¹ band (near-zero solar weight) now hard-crashes the run at first forcing read rather than clipping. The strictness buys little since the moment is clipped anyway; consider `np.clip(g, 0.0, 1.0)` (consistent with the "non-negative optical depths" contract) or at least a tolerance.

4. **INFO — `loaded[:4] + (loaded[4],)`** (`external.py`, `get_aerosol_sw_volcanic_optics_at_time`): yes, simplify to `loaded[:5]` if touching the file again. Cosmetic only.

5. **Checked, clean (for the record):** energy/double-count — volcanic SW is removed from the grey `aerosol_od` exactly when the optics path is active (`_trop_cfg` swap), CCN stays tropospheric, and the moment mixing in `_mix_sw_aerosol_and_clip` is the exact OD-weighted combination with the AD-safe `safe_divide` reused (budget-closure test passes); pytree — `aerosol_sw_volc` appended last with default `None`, added to `GRID_SHAPED_FORCING_FIELDS`, shard on dim 0 correct for 4-D; halo layout — overhead zero-prepend, `[::-1]` flip, `_add_halos`, clip mirror the grey path and moments are linear so the extrapolation is exact; chunked host interpolation — per-column independence holds (column-chunk test asserts array-equal); clear-sky-with-aerosol convention unchanged from the grey path (both aerosols excluded from `sw_fluxes_clr`, pre-existing); no-file / legacy-column behavior — loader returns `None`, column `aod` stays in the grey field, byte-identical (test pins it).
