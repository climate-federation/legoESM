Verdict: the core re-anchor fix is correct, but I would not call the packet fully closed.

- Round-2 #1/#2 are resolved for the surface-anchor path. SST/SIC are cached canonically, then `T_sfc` is re-blended after every skin update; the next loop iteration copies that value into its forcing. Both radiation and MPAS turbulence consume the traced `forcing["T_sfc"]`. See [model_driver.py:6737](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6737), [model_driver.py:6830](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6830), [radiation integration:997](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/atmosphere/legoesm/atmosphere/physics/radiation/integration.py:997), and [turbulence integration:590](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/atmosphere/legoesm/atmosphere/physics/turbulence/integration.py:590). Held-radiation steps retain prior SW/LW while refreshing turbulent fluxes, so the skin still advances each model step. [primitive_eq_mpas.py:746](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/atmosphere/legoesm/atmosphere/dynamics/gcm/primitive_eq_mpas.py:746)

- The midpoint restart anchor branch is also fixed: restored skin is adopted before the forced initial daily-boundary sample, which blends against the restored skin. [model_driver.py:6212](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6212), [model_driver.py:6657](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6657)

- However, exact feature-on split invariance still is not demonstrated under ice. With radiation subcycling, restart step 0 forces a new radiation solve while the uninterrupted run may use retained SW/LW; those retained fluxes directly enter the skin update. [model_driver.py:6777](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6777), [model_driver.py:6805](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6805). This is the acknowledged existing radiation branch, not another stale-anchor branch—but it now directly affects skin evolution. The new integration test cannot detect it because `sic=0` resets every skin value to `T_freeze_ocean`. [test_mpas_ice_skin.py:237](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/tests/unit/test_mpas_ice_skin.py:237)

- Finding #3 has no remaining silent strip path: the fallback writes staged skin. [model_driver.py:4268](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:4268) But ordinary modern checkpoints also stage `physstate_*`; load→save-without-run then raises before reaching that fallback. [model_driver.py:4152](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:4152) So it is safe from stripping, but not a successful general load→save operation.

New issue: the feature-on shape guard is bypassable. A scalar SST/SIC broadcasts against the skin vector, producing `(nCells,)` and passing `_ts0`’s output-only shape check. The same scalar is then cached and broadcasts through the update. [model_driver.py:6212](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6212), [model_driver.py:6253](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6253), [model_driver.py:6740](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6740). Validate raw SST and SIC shapes explicitly before blending.

Also harden checkpoint loading: skin validation currently only checks flattened size, not original shape, floating dtype, finiteness, or `[floor, T_freeze]` bounds. A NaN skin can poison even `sic=0` anchors via `0 * NaN`. [model_driver.py:6212](/work/bd1083/b309178/diffESM/legoesm_pg/legoESM/packages/coupler/legoesm/driver/model_driver.py:6212)

Feature-off numerical behavior is equivalent; the split merely adds redundant `jnp.asarray` calls. It is not literally source-byte-identical. The added re-blend is opt-in-only and an eager `O(nCells)` JAX dispatch each step; likely small relative to MPAS physics, but not fused, so benchmark it rather than claiming free performance.
