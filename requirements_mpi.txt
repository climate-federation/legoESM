# MPI workload version pins for legoESM.
#
# Why this exists
# ---------------
# For a long time mpi4jax 0.8.x used the legacy XLA ``custom_call`` API
# (``API_VERSION_STATUS_RETURNING``) that JAX progressively removed:
#   * JAX <= 0.7: CustomCallV1 + V2 fully supported.
#   * JAX 0.8:  XLA:CPU dropped STATUS_RETURNING (mpi4jax 0.8.x uses it) -> slow.
#   * JAX 0.9:  CustomCallV1 deprecated; STATUS_RETURNING warns + slow path.
#   * JAX 0.10: CustomCallV1 fully removed -> mpi4jax 0.8.x breaks.
# legoESM's old pins landed in the bad overlap, so CPU-MPI scaling numbers were
# a pessimistic lower bound (mpi4jax API overhead, not hardware comms cost).
#
# RESOLVED (issue #567): mpi4jax 0.9.0 shipped the FFI rewrite (mpi4jax#289).
# The collectives now use JAX's modern FFI mechanism, so they NO LONGER emit the
# STATUS_RETURNING warning and survive the legacy-API removal in JAX 0.10.
# Validated np=2 on Ginsburg (Linux, openmpi, jax 0.9.1): mpi4jax 0.8.1 emits
# STATUS_RETURNING for mpi_allreduce, 0.9.0 does NOT (allreduce numerics match).
# This file therefore pins the FFI mpi4jax 0.9.x; CPU-MPI scaling is meaningful.
#
# Note: mpi4jax 0.9.x builds its FFI extension from source (nanobind), so a
# modern C++ compiler + an MPI toolchain (``mpicc``) must be available at install
# time (export ``MPICC=$(which mpicc)``).
#
# How to use
# ----------
# 1. python3.11 -m venv .venv-mpi && .venv-mpi/bin/pip install --upgrade pip
# 2. .venv-mpi/bin/pip install -e .
#    MPICC=$(which mpicc) .venv-mpi/bin/pip install -r requirements_mpi.txt
# 3. JAX_PLATFORMS=cpu JAX_ENABLE_X64=1 mpirun -np 4 \
#        .venv-mpi/bin/python scripts/bench/... ...
#
# Validation
# ----------
# Verified by tests/distributed/test_mpi_differentiability.py under the CI
# mpi-distributed.yml job. Local:
#   .venv-mpi/bin/python -m pytest tests/distributed/ -q
# runs mpirun -np 2 with NO STATUS_RETURNING fallback warning.
#
# When you can DROP this file
# ---------------------------
# Once the default project install resolves mpi4jax >= 0.9 (FFI) together with a
# JAX the rest of legoESM supports, the default install is scaling-safe and this
# pin file can be deleted.

# FFI-compatible pair: mpi4jax 0.9.0 (the FFI rewrite) + JAX 0.9.x. The legoesm
# runtime guard (parallel/reductions.py) declares the tested range
# "jax>=0.8.0,<0.10.0" + "mpi4jax>=0.8.0,<0.10.0"; jax 0.9.2 + mpi4jax 0.9.0
# lands inside it on the FFI (no-warning) path.
jax==0.9.2
jaxlib==0.9.2
mpi4jax==0.9.0
mpi4py>=4.0,<5.0

# numpy major compatible with the JAX 0.9 stack.
numpy>=2.1,<2.3
